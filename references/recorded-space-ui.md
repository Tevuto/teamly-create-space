# Маршрут по записи Playwright

Использовать как подсказку по интерфейсу Teamly. Маршрут получен из записи пользователя. Перед каждым действием подтвердить экран, видимость и однозначность элемента. Начальный URL брать из текущего задания.

| Шаг | Что было в записи | Как проверить перед продолжением |
|---|---|---|
| Открыть мастер | В меню создания выбрать пункт «Создать пространство» и кнопку внутри него | Видны поля мастера. Первые кнопки записи не имеют надёжных семантических признаков. Определить вход в меню по текущему экрану |
| Заполнить паспорт пространства | Поля с `data-test-id="create-space-popup-title"` и `data-test-id="create-space-popup-description"`. Кнопка `data-test-id="create-space-popup-confirm-button"` | Сверить название и описание с заданием. После клика дождаться экрана настроек |
| Настроить пространство | Экран с параметрами «Свойства», «Быстрые ссылки», «Глоссарий», «Связанный диск», правилами экспорта и прав редакторов/администраторов | Текущее и целевое состояние проверять по каждому параметру. Клики в записи показывают взаимодействия, но не итоговые значения. Применять заданные значения, остальные параметры сохранять. Кнопку подтверждения искать в текущем шаге мастера |
| Выбрать начальный шаблон | На следующем экране выбрать «С нуля» и нажать кнопку подтверждения | Для пустого каркаса проверить выбранный вариант, затем дождаться открытия пространства. Сверить название, хост и URL, записать подтверждённый URL в паспорт |
| Создать раздел | Открыть меню создания внутри подтверждённого узла родителя. Выбрать `data-test-id="create-article-button"`, заполнить `data-test-id="article-title"`, использовать «Опубликовать» для опубликованной статьи | Сверить родителя перед созданием. После создания дождаться нового URL и пустого черновика перед вводом. После сохранения проверить название, URL и положение по текущей странице и дереву. Перед повторной попыткой проверить также черновики, если они доступны |
| Поставить обложку | В открытой статье выбрать «Добавить обложку» → «С компьютера», затем загрузить файл в появившемся контроле загрузки | Сверить пропорции файла с рамкой Teamly. В предпросмотре подогнать масштаб и положение по видимым границам. Если кадр обрезает важные элементы, расширить фон изображения или пересобрать композицию и загрузить снова. Применить обложку через фактический контрол сохранения. Запись заканчивается в настройках статьи, подтверждения сохранения обложки в ней нет. Повторно открыть статью и проверить изображение и карточку |

## Обложки

Подготовить разные композиции в стилистике Teamly. Ориентиры палитры: #21104D, #6648F5, #3984F6 и #19C9F2. Оставить безопасные поля и минимум мелкого текста. До подготовки серии сверить рамки текущего редактора. В тесте были форматы 5:1 и 2,5:1. В предпросмотре подогнать масштаб и положение для каждого формата, при необходимости разъединить области. Если важные элементы не помещаются, расширить фон или пересобрать композицию. Сохранить и дождаться появления загруженной обложки. Проверить, что текст, логотип и главный объект целиком видны в статье и карточке. При возобновлении переиспользовать проверенные обложки.

## Эмодзи рядом с заголовком статьи

Открыть целевую статью и область её заголовка. Выбрать «Добавить эмодзи» именно у заголовка, затем в открывшейся панели выбрать один тематический эмодзи. Для отдела продаж подходят 📈 для воронки, 💬 для встреч и 📊 для примеров ТБД.

В записи пользователя кнопка заголовка была вторым совпадением, а в панели была одна кнопка с недавним эмодзи ⚒️:

```js
await page.getByRole('button', { name: 'Добавить эмодзи' }).nth(1).click();
await page.getByRole('tabpanel')
  .filter({ hasText: 'Недавние ⚒️ Вы еще не выбрали эмодзи' })
  .getByRole('button').click();
```

Позицию кнопки и содержимое «Недавних» сверять по текущему интерфейсу. По возможности ограничивать поиск областью заголовка, а в открытой панели выбирать конкретный символ по его подписи или видимому значению. При неоднозначном совпадении уточнить локатор перед кликом. После сохранения проверить эмодзи рядом с заголовком и на карточке, если она его отображает.

## Плагин «Вывод вложенных статей» на разводящей странице

1. Открыть разводящую статью в редакторе. Проверить, есть ли нужный блок в теле. Если блока ещё нет, поставить курсор в месте вставки и открыть меню инструментов редактора.
2. Выбрать «Вывод вложенных статей». В записи пользователя это следующие действия:

```js
await page.locator('.dropdown.editor-menu-dropdown > .dropdown__trigger > .simple-button.dropdown__trigger-button').click();
await page.getByRole('button', { name: 'Вывод вложенных статей', exact: true }).click();
```

Заключительный клик по пустому абзацу в записи переводит фокус. При необходимости выбрать конкретный абзац рядом со вставленным блоком. Сверить результат по самому блоку внутри тела. Если разделы ещё пусты, проверить карточки после создания дочерних статей.

## Большие карточки на разводящей странице

1. Найти вставленный плагин «Вывод вложенных статей» в теле статьи.
2. Открыть меню формата в этом блоке. Если совпадений по классу несколько, ограничить поиск нужным блоком.

```js
await page.locator('.simple-button.nested-articles-dropdown__btn').click();
await page.getByRole('button', { name: 'Большие карточки', exact: true }).click();
```

Проверить, что формат применился и видны карточки с обложками. Сверить названия и ссылки. Проверить формат после завершения сохранения. При неоднозначном статусе открыть разводящую обычным переходом внутри Teamly.

В записи используется атрибут `data-test-id`. Использовать точный селектор атрибута либо явно настроить Playwright на него для `getByTestId`. Искать внутри текущего мастера или редактора, если тот же идентификатор присутствует в других частях страницы.

Для дерева привязывать действия к узлу родителя по сохранённому URL либо по точному названию в нужной ветке. Внутри подтверждённого узла искать его собственный контрол создания. Позиционные селекторы `.first()`, `.nth()`, `nth-child`, классы активного узла и идентификаторы онбординга из записи не использовать как идентификаторы родителя. Если целевой контрол нельзя найти однозначно, остановить зависимый шаг и сохранить причину в паспорте.

Запись также содержит создание суперстатьи, рабочих статей и ТБД, а также удаление случайной статьи. Эти операции находятся за пределами сценария сборки каркаса. Для проверки повторяемости выполнить один раздел в тестовом пространстве, затем повторить запуск с отсутствующим URL раздела в паспорте. После сверки должен сохраниться один раздел с тем же URL. После неизвестного результата финального подтверждения мастера сначала сверить список пространств. Повторный запуск мастера допустим после подтверждения, что целевого пространства нет.
