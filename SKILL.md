# Создание пространства Teamly

Использовать URL и контекст из текущего задания. При продолжении открыть актуальный [паспорт](references/demo-passport.md). Без URL подготовить план и запросить ссылку. Найти доступную интеграцию или разрешённое управление браузером. При отсутствии доступа отметить статус «спроектировано».

Полный каркас включает корневую статью и пять разводящих разделов, шесть тематических эмодзи и обложек, плагин «Вывод вложенных статей» с большими карточками и права корневой. Для точечного запроса выполнять только его объём. Для суперстатьи используй `$teamly-superarticle`, для рабочих статей и ТБД — `$teamly-demo-articles`. Передай актуальный паспорт, URL корневой и разделов. Курсы выполняй по сценарию пользователя отдельно. Для подготовки шести обложек используй `$teamly-host-visual-designer`. Следуй выбранному пользователем стилю или уже оформленной серии. При воспроизведении записи используй её палитру. Для новой серии без выбранного стиля используй палитру навыка изображений.

## Пакетная сборка в Code Mode

Для создания пространства и заполнения корневой с пятью разделами сначала подготовь паспорт, тексты и один JSON-план по [инструкции сборщика](references/code-mode.md). Запускай `scripts/teamly-code.mjs` из установленной папки `teamly-superarticle`. Для работы в существующем пространстве укажи его URL и передай известные ссылки из паспорта. Проверь план командой `check`, затем выполни `build` с одним профилем Chrome и файлом состояния. Перенеси сохранённые ссылки и статусы в паспорт.

Подключай обложки, эмодзи, нативные карточки, настройки мастера и доступ к корневой как проверяемые UI-шаги, если маршрут подтверждён в текущем Teamly. Для неподтверждённого маршрута продолжи в редакторе по справкам ниже. Заверши те же проверки кадрирования, пяти карточек и наследования прав. При сбое используй тот же план и файл состояния.

## Выполнение

1. Проверить хост, пространство и дерево. Использовать существующее пространство из задания. Новое создавать по поручению и после поиска совпадений. Использовать автоматически созданную корневую, если она есть.
2. До изменений завести паспорт. Подготовить одним пакетом названия, краткие тексты и эмодзи для корневой и пяти разделов. Четыре темы выбрать по задачам клиента, пятый раздел — «Примеры использования ТБД». Определить рамки обложек на первом объекте и подготовить шесть тематических изображений одной серией.
3. Обрабатывать по одной статье. Найти её по URL из паспорта или точному названию в нужной ветке. Если статьи нет, открыть создание под проверенным родителем. **Дождаться нового URL и признаков пустого черновика до ввода текста.** Ввести заголовок и текст, поставить эмодзи, вставить в тело «Вывод вложенных статей», оформить обложку и сохранить. Если UI требует сперва опубликовать статью, завершить оформление на той же странице. Проверить подтверждение сохранения, заголовок, расположение и обложку. Сразу записать ссылку и результат в паспорт. Если работа прервалась после нажатия кнопки, сначала проверить дерево и черновики, затем продолжить с первого непроверенного действия.
4. После появления разделов открыть корневую одним обычным переходом. В блоке в теле выбрать «Большие карточки», если формат ещё не выбран. Сверить пять названий, обложки и целевые URL с паспортом. Для пустых разделов отложить проверку карточек до наполнения. Для объектов без нативных карточек добавить рабочие ссылки после их создания.
5. При наличии согласованной матрицы открыть [инструкцию по доступу](references/access.md). Для полного демо нужны пять пользователей, два отдела и одна группа. При недостающих данных завершить каркас и отметить, что требуется для настройки и проверки наследования.
6. Вернуть ссылку на корневую и паспорт, фактические количества, статус прав и ближайший шаг. Отдельно указать непроверенные пункты.

## Полная сборка пространства с курсом

Для полного пространства в проекте «ХОСТ ПРОДАЖ» используй `teamly-space-pilot.mjs`. Подготовь план, обложки, наполнение суперстатьи и вложенных, рабочие статьи, таблицы и курс. Выполни локальный `check`, затем один `build` с этими файлами. Он всегда сохраняет отчёт о сборке в Markdown и JSON. Через `--report` можно задать путь. Отдельный проход мастера в браузере не требуется.

Глоссарий, быстрые ссылки, связанный диск и свойства включай сразу в мастере. Для 22 статей используй зашитый в сборщик набор разных эмодзи по позициям. После команд создания сохраняй ссылки. При сбое сверяй только проблемный объект по боковой панели и продолжай с него. После публикации исходных статей заполняй умные таблицы и собирай курс параллельно. Полная сверка идёт после обеих веток. За одно открытие каждой ТБД проверь строки, свойства и представления. Сохраняй идентификатор нового столбца до подтверждения окончательного имени. При сбое настройки представления продолжай с него и сохраняй подтверждённые строки. Статьи для сверки открывай в конце.

При подготовке полного пространства выдели один раздел с тремя текстовыми инструкциями для одного ИИ-диалога из 5–6 реплик и сохрани реестр ссылок на картинки в общей папке Google Drive. Заполни `demo.images` и `demo.aiSearch` по формату в `teamly-demo-articles/references/full-demo-space.md`. После выполнения верни отчёт с общим временем, разбивкой по этапам, сценарием показа, ключом курса и последовательностью запросов ИИ.

## Как читать справку и проверять экран

- В [маршрутах Playwright](references/recorded-space-ui.md) читать только блок текущей операции. Полный снимок интерфейса использовать для незнакомого экрана или ошибки.
- Объединять последовательные действия в одном вызове до смены экрана или сохранения. После перехода проверять нужный URL и признак готовности редактора. После сохранения дождаться загрузки на текущей странице и проверить нужный результат по короткой выборке.
- Обычный переход внутри Teamly использовать для итоговой сверки. Перезагрузку или повторное открытие применять при неизвестном результате, устаревшем состоянии или отсутствии надёжного признака сохранения.
- При нескольких совпадениях отметить конфликт в паспорте и продолжить независимую работу. При неизвестном результате создания сначала сверить фактическое состояние, включая черновики.
